# ADR-002 · 翻译墙分类：P / A / D / E / S 五类

- 日期：2026-09-09
- 状态：已采纳

---

## 背景

实测发现「阻碍拿到可翻译原文」的障碍形态多样，需要统一建模，便于检测、策略编排与站点适配器开发。

## 决策

「翻译墙」= 阻碍浏览器拿到可翻译原文的一切障碍，统一分为五类：

| 类别 | 全称 | 症状 | 根因 | 突破手段 |
|---|---|---|---|---|
| **P** | 订阅墙 Paywall | 正文截断/模糊，仅前几段 | 服务端只返回摘要 | archive.is 快照 / 引导互补扩展 |
| **A** | 反爬墙 Anti-Bot | 空白页 / Cloudflare 挑战 / 403 | 浏览器指纹 + 频率 + Cookie 污染 | 清 Cookie / 等待挑战 / 引导互补扩展 |
| **D** | 动态墙 Dynamic | 文本异步渲染、滚动才出现 | SPA 懒加载 | MutationObserver 增量补翻 |
| **E** | 嵌入墙 Embedded | 内容藏在 iframe / 字幕 / PDF | 跨域隔离 | same-origin 注入 / 提示打开源地址 |
| **S** | 结构墙 Structure | 有文本但翻译错乱/翻错对象 | 特殊 DOM（社交/多列/评论） | 站点适配器规则 |

## 关键认知

**墙是事后分类，不是事前检测。**
- 访问站点 → 发现翻不对 → 写适配器解决 → 回头贴标签（如 x.com = S+D）
- 不是先检测"墙类型" → 再找通用策略
- 同类墙在不同站点实现完全不同，不存在通用"结构墙策略"

## 编排顺序

多墙叠加按 **P → A → D → E → S** 顺序编排，直到拿到干净原文。

## 处理原则

- **能处理**：免费文/subscription wall 有快照 → 走策略
- **处理不了**：hard paywall + CF challenge → **提示用户手动**，不死磕（用户 2026-09-09 确认："目前就给提示，然后就不处理了"）

## 后果

- ✅ 墙检测器 `wall/detector.js` 产出 `{status, walls[], evidence, coverage}`
- ✅ 站点适配器按分类渐进补充
- ⚠️ 实际遇到的墙以 P（订阅）+ S（结构）为主；A/D/E 理论存在但少见，预留接口不预实现
