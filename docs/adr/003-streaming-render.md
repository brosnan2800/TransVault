# ADR-003 · 流式渲染 + 视口优先排序

- 日期：2026-09-09
- 状态：已采纳

---

## 背景

用户反馈 TransVault 翻译慢，"沉浸式翻译很快，我这里要等半天"。

## 测量（基线）

用 Playwright 在 Washington Post 文章页（150 段）计时：

```
t=509ms    count=0   ← 用户盯着空页面
t=20850ms  count=150 ← 全部译文同一瞬间出现（全翻完才渲染）
首字延迟 20.8s | 从首字到完成 0ms
```

## 根因

原 `translatePage()` 流程：收集全部段落 → 分批翻译 → **await 全部完成** → 一起渲染。用户在整个翻译期间看不到任何输出。

辅助因素：无视口排序（按文档顺序翻，视口外先翻）、observer 滞后启动（SPA 重渲染期间无人补翻）。

## 决策

1. **流式渲染**：`translateBatch()` 每个批次完成立即回调渲染，不再等全部。
   ```
   改前：collect → translate(全部) → render(全部)
   改后：collect → translate(批1) → render(批1) → translate(批2) → render(批2)...
   ```
2. **视口优先**：`sortByViewport()` 屏幕内段落排最前。
3. **observer 提前**：`enableObserver()` 在翻译开始前启用，捕获 SPA 重渲染后重建的段落（命中缓存秒回）。

## 预期效果

- 首字延迟：20.8s → 首个批次返回时间（通常 <3s）
- 感知体验：用户 2 秒内看到当前屏幕区域的译文

## 验证方式

`scripts/compare_translate.mjs` 输出 `⏱ 速度: 首个译文 Xms | 累计10段 Yms | 插入跨度 Zms`：
- 插入跨度 < 1500ms → 集中渲染（未生效）
- 插入跨度大 → 渐进流式（生效）

## 后果

- ✅ 感知延迟大幅下降
- ⚠️ 渲染碎片化：批次交错渲染，每批独立样式节点（由 `.transvault-trans` 统一约束）
- ⚠️ 竞态风险：SPA 重渲染删除已渲染译文 → 由提前启用的 observer 补翻兜底（依赖缓存命中）
